Create a pull request for the current branch following the DSCI 575 repo standards.

## Pre-flight checks

Before creating the PR, verify:

1. Not on a protected branch: `git branch --show-current` — must not be `main` or `dev`.
2. All tests pass: `make test` (90% coverage gate enforced).
3. Type check passes: `make typecheck`.
4. Linters pass: `make lint`.
5. Working tree is clean: `git status`.

If any check fails, stop and fix the issues before proceeding.

## Collect metrics

```bash
pytest tests/ --cov=src --cov-report=term-missing 2>&1 | tail -20
```

Extract the coverage percentage from the `TOTAL` line to report in the PR body (optional — the repo template does not require it, but it's helpful context).

## PR format

**Title:** concise, imperative, matches commit format (no `[AI]:` prefix).

Examples:
- `feat: add hybrid retriever reranking`
- `fix: handle empty query in BM25 search`
- `docs: document corpus contract in CLAUDE.md`

**Body:** populate `.github/PULL_REQUEST_TEMPLATE.md`:

```
Fixes #<issue_number>

### Proposed Changes
  - <change 1>
  - <change 2>
  - <change 3>
```

Ask the user for the issue number if not obvious from the branch name or commit trail. If there is no linked issue, use `Fixes #n/a` or remove the line.

## Create the PR

```bash
git push -u origin <current-branch>
gh pr create --base dev --title "<type>: <title>" --body "$(cat <<'EOF'
Fixes #<issue_number>

### Proposed Changes
  - <change 1>
  - <change 2>
  - <change 3>
EOF
)"
```

Default base branch is `dev`. Confirm with the user before targeting `main` (reserved for releases).

Return the PR URL when done.
